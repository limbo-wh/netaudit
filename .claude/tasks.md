## Найдено при запуске 2026-08-17

- [x] `PingLogger` печатал `HH:mm:ss` от `DateTimeOffset.UtcNow`, а имя файла и
      заголовок сессии — от локального времени. Лог расходился сам с собой на 3 часа.

- [x] `PingLogger` округлял RTT до целых (`F0`) — в локальной сети все строки

- [ ] **1.1.1.1 на этой машине перехватывается локально.** Независимый `ping` даёт
      `time<1ms TTL=128` — это ответ соседней Windows-машины, а не Cloudflare
      (у настоящей был бы TTL ≈ 50–60 и десятки мс). Значит серия L3 «интернет»
      сейчас меряет не интернет. Проверять `reply.Options.Ttl` и предупреждать в UI,
      когда якорь отвечает подозрительно близко. Заодно это разъяснится на этапе 1,
      когда появится traceroute

## Строка FPS в оверлее (2026-08-17)

- [x] `FpsProbe`: счёт событий Present провайдеров DXGI и D3D9 через ETW.
      Тот же способ, что у PresentMon от Microsoft

- [x] **Найден и исправлен настоящий баг, из-за которого счётчик всегда показывал
      прочерк.** `_session.Source.AllEvents` отдаёт «сырые» события без разбора
      манифеста — `TaskName` для DXGI/D3D9 приходил как `"EventID(42)"`, а не
      `"Present"`, потому что их манифест зарегистрирован в системе через
      wevtutil (путь TDH), а не разослан динамически по ETW — именно
      динамический путь понимает голый `Source.AllEvents`. Фильтр по имени
      не находил вообще ничего, `Available` при этом оставался `true`,
      никакой ошибки не было — просто событий с нужным именем не приходило
      никогда. Исправлено на `RegisteredTraceEventParser`, который резолвит
      имена через TDH правильно
- [x] Заодно исправлена вторая, более тонкая ошибка: фильтр был `Contains("Present")`,
      а у DXGI три разных семейства событий с «Present» в имени — `Present`,
      `IDXGISwapChain_Present`, `PresentMultiplaneOverlay`. При рабочем
      резолвинге имён это утроило бы счётчик. Заменено на точное `== "Present"`
- [x] **Проверено на живой Dota 2, права администратора получены через elevation
      на этой же машине.** Отдельный диагностический консольный инструмент

      = 52,6 FPS у dota2.exe — правдоподобное число, не через край и не ноль.

      корректность подсчёта
- [x] Добавлена самодиагностика: `FpsProbe.EventsSeen`/`PresentsMatched`
