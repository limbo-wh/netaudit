# NetAudit — точка входа для агента

Локальная Windows-утилита аудита сети в реальном времени с оверлеем поверх игр.
Серверной части нет, всё работает на машине владельца.

## Обязательно перед началом работы

Прочитать целиком, в этом порядке:

1. `.claude/rules.md` — правила работы, запреты, границы самостоятельности
2. `.claude/stack.md` — стек, версии, ключевые технические решения
3. `.claude/skeleton.md` — карта репозитория: что где лежит и чего ещё нет
4. `.claude/tasks.md` — список задач, отсортирован по приоритету

Первоисточники (менять только по просьбе владельца):
`2026-08-16_netaudit_windows_инструкция_и_ТЗ.md` — рабочее ТЗ,
`2026-08-16_netaudit_desktop_windows_analysis.md` — обоснование решений.

## Обязательно по ходу и в конце работы

Файлы в `.claude/` — живые, их надо поддерживать, а не только читать:

- изменилась технология или решение → обновить `stack.md`;
- добавился/удалился файл или проект → обновить `skeleton.md`;
- задача сделана или появилась новая → обновить `tasks.md` **сразу**, а не в конце;
- правило оказалось неверным, устаревшим или неполным → **исправить `rules.md`**
  и сказать об этом владельцу.

Новые задачи заводить в момент обнаружения. Всё замеченное и не сделанное должно
осесть в `tasks.md`, иначе потеряется.

## Коротко

- Язык всего текста, комментариев и UI — русский.
- Проверка перед сдачей: `dotnet build "NetAudit\NetAudit.slnx"` без ошибок.
- Что нельзя проверить на этой машине — помечать `[?]` в `tasks.md`,
  а не выдавать за проверенное.
- Красная линия: никаких хуков DXGI/Present и инъекций DLL в процесс игры —
  это бан античитами. Для exclusive fullscreen только RTSS.
  
  ## Роли агентов

- Claude Code — основной агент: сложные задачи, ядро проекта, интеграция частей,
  git, целостность репозитория. Финальное слово по коду — за Claude.
- Grok — дополнительный агент для мелких и изолированных задач: наброски,
  ассеты, варианты UI, вычитка/резюме текстов, анализ директорий, рутинные
  правки по чёткому ТЗ. НЕ ядро проекта, НЕ архитектурные решения.
- Количество параллельных агентов не ограничено; время выполнения задач
  не ограничено — можно раздавать несколько задач и спокойно ждать.
- Ошибки на стороне Grok правит Claude (или возвращает задачу Grok
  с уточнённым spec) — ответственность за результат всегда на Claude.

### Делегирование Grok — оркестрация Orca ADE (основной путь)

Проверенный цикл (все команды выполняет сам Claude через PowerShell):

1. `orca status --json` — проверить runtime (должен быть `ready`).
2. `orca orchestration run-create --objective "..." --json` — создать Run;
   координатором становится текущий терминал.
3. `orca orchestration task-create --task-title "..." --spec "..." --json` —
   в spec ЯВНО прописать: границы задачи, формат результата, что трогать
   запрещено (worker'ы следуют ограничениям из spec).
4. `orca orchestration worker-start --task <taskId> --worktree current|new-child --agent grok --json`
   — `current` для read-only и мелочей; `new-child` для правок кода
   (учитывать: новая копия репозитория = переимпорт/пересборка артефактов).
5. `orca orchestration check --wait --types worker_done,escalation,question --timeout-ms <N> --json`
   — блокирующее ожидание (CLI шлёт keepalive каждые ~15 сек).
6. `check --ack <deliveryId>`, затем `worker-release --dispatch <dispatchId>` —
   закрыть worker и заархивировать транскрипт. Статус задачи станет
   `completed` автоматически.

Отладка: `task-list`, `worker-read --dispatch <id>`, `worker-stop`,
`worker-start --retry-of <dispatchId>`. Групповые адреса (`--to "@grok"`) в
PowerShell — обязательно в кавычках. Полная справка:
`orca skills get orchestration --full`.

Запасной путь (если Orca недоступна): мост grok-build внутри Claude Code —
`/grok-build:check` (проверка готовности), `/grok-build:delegate` (передача задачи).

### Правила делегирования

- Делегировать только задачи с чётким, проверяемым результатом; spec пишется
  так, чтобы задачу можно было выполнить без вопросов.
- Результат Grok всегда проверяется Claude перед интеграцией (вычитка/диф).
- Инструменты с состоянием (редакторы, MCP-серверы, БД, деплой) — только
  Claude; worker'ам в spec это явно запрещать.
- Проектные ограничения дописываются здесь же, под этим блоком
  (пример: «worker'ам запрещено запускать Godot и MCP-инструменты»).
